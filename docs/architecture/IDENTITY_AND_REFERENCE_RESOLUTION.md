# Paperazzi — Identity and Reference Resolution Architecture

This document is normative for Phase 4.

## 1. Core principle

Paperazzi must distinguish **source mentions** from **resolved semantic entities**.

```text
source creator mention != person identity
raw reference          != cited paper
```

Resolution is an evidence-backed, reversible layer above Phase 3 persistence. Source rows are never rewritten to make a later decision look original.

## 2. Author identity model

### 2.1 Canonical author

A canonical author represents a Paperazzi identity cluster, not a Zotero creator row.

Recommended durable tables:

```text
authors
author_name_variants
author_external_ids
author_identity_memberships
author_identity_decisions
author_identity_evidence
authorships
authorship_evidence
```

`author_id` should be generated by Paperazzi and remain stable. Use an application-generated sortable identifier such as UUIDv7/ULID if the existing database conventions support it; do not derive identity from a name, DOI, email address or Zotero creator ID.

### 2.2 Mention membership

`author_identity_memberships` links a Phase-3 `paper_creator_mentions.creator_mention_id` to a canonical `author_id`.

A membership requires explicit status and provenance:

```text
CANDIDATE
ACCEPTED
REJECTED
SUPERSEDED
```

At most one active `ACCEPTED` membership may exist for one creator mention.

The creator mention itself remains immutable source projection except for ordinary Phase-3 Zotero synchronization.

### 2.3 Name normalization

Store the original name exactly as sourced and derive normalized blocking forms separately.

Useful normalized features may include:

- Unicode normalization;
- whitespace/punctuation normalization;
- case-folded forms;
- `family + given` and `given + family` forms;
- initials;
- diacritic-insensitive search form;
- transliteration/search aliases when explicitly generated and tagged as derived.

**A normalized-name match alone must never auto-merge two people.**

Common names, initials, name-order differences and transliteration collisions make that unsafe.

### 2.4 Evidence hierarchy

Identity evidence should be typed, scored and retained individually.

Strong signals:

```text
ORCID exact
other authoritative person identifier exact
same explicit author email with compatible chronology/context
manual confirmed same-person decision
```

Supporting signals:

```text
full-name compatibility
coauthor overlap
affiliation overlap
publication chronology
research-topic compatibility
corresponding-author email evidence
stable local collaboration neighborhood
```

Negative/conflict signals:

```text
explicit different ORCID
incompatible full names
simultaneous incompatible affiliations where identity is implausible
manual NOT_SAME_PERSON decision
strongly contradictory publication/person evidence
```

Zotero `creatorID` may be stored as source provenance but is **not an authoritative person identifier**.

### 2.5 Decisions are reversible

Do not physically merge source creator rows or delete the losing identity history.

Identity operations should be represented as decisions/events:

```text
CREATE_IDENTITY
LINK_MENTION
UNLINK_MENTION
MERGE_IDENTITY
SPLIT_IDENTITY
NOT_SAME_PERSON
LOCK_IDENTITY
UNLOCK_IDENTITY
```

Each decision records:

- actor: deterministic / local AI / manual;
- algorithm/prompt/model version when applicable;
- evidence IDs;
- previous state;
- resulting state;
- timestamp;
- notes/reason code.

Manual locks prevent automatic resolvers from silently undoing a confirmed decision.

## 3. Authorship semantics

`authorships` is the resolved author-paper relation.

Recommended core fields:

```text
authorship_id
author_id
paper_id
creator_mention_id
order_index
creator_type
is_first_author
is_corresponding_author
corresponding_status
created_at / updated_at
```

### First author

First-author status is deterministic from the ordered accepted author creator mentions for the paper. Do not infer first authorship from display order after identity merging.

### Corresponding author

Corresponding author is paper-specific.

Allowed evidence sources include:

- explicit structured Zotero metadata if supported and trustworthy;
- accepted PDF correspondence spans;
- accepted author-email/asterisk mapping;
- manual confirmation.

Do not assign corresponding author merely because an email address appears somewhere in the PDF.

### Affiliation evidence

Affiliation is also time/paper-specific evidence. Phase 4 may resolve accepted affiliation spans to an authorship when defensible, but should not yet attempt a full global institution ontology.

## 4. Reference resolution model

### 4.1 Acceptance boundary

Only:

```text
paper_references.acceptance_status = ACCEPTED
```

may enter semantic reference matching.

`CANDIDATE`, `REJECTED` and `SUPERSEDED` reference rows are excluded from automatic citation resolution.

### 4.2 Match flow

```text
accepted paper_reference
        ↓
normalized bibliographic features
        ↓
0..N local candidate papers
        ↓
match scoring / contradiction checks
        ↓
CANDIDATE / ACCEPTED / REJECTED / UNRESOLVED
```

`paper_reference_matches` remains the authoritative resolution table. A graph `CITES` relation is derived later from accepted matches; it is not written directly by the resolver.

### 4.3 Match classes

Use explicit match types:

```text
DOI_EXACT
TITLE_EXACT_NORMALIZED
AUTHOR_YEAR_JOURNAL
JOURNAL_VOLUME_PAGE_YEAR
BIBLIOGRAPHIC_COMPOSITE
AI_RESOLVED
UNRESOLVED
```

### 4.4 Automatic acceptance policy

A resolver may auto-accept only when the evidence is both strong and unambiguous.

Minimum conservative policy:

- unique normalized DOI exact match with no contradiction: eligible for automatic acceptance;
- title exact normalized alone: candidate only unless reinforced by year/author/venue;
- bibliographic composite: accept only above a documented threshold and with a clear margin over the second candidate;
- ambiguous one-to-many results: review queue;
- contradiction with DOI/title/year: do not force a match.

The matcher must preserve the score components that produced the decision.

### 4.5 DOI is sparse

Phase 2.5/3 showed that DOI identifiers are sparse in reference text. Therefore reference resolution must not be DOI-centric. Composite bibliographic matching is a first-class path, while DOI exact remains the strongest shortcut when present.

## 5. Candidate scoring

Scores are aids to decision, not hidden truth.

Store individual components, for example:

```text
name_score
coauthor_score
affiliation_score
year_score
title_score
venue_score
volume_page_score
identifier_score
conflict_penalty
```

Do not store only one opaque confidence number.

All thresholds must be centralized/versioned so a later resolver version can reproduce or supersede older decisions.

## 6. AI role

Local AI may:

- inspect ambiguous identity candidates;
- explain why two mentions are likely same/different;
- inspect accepted local evidence;
- resolve difficult bibliographic references;
- produce structured decisions with evidence IDs.

Local AI may not:

- directly mutate Zotero;
- silently merge authors without a persisted decision;
- use unaccepted PDF evidence as authoritative fact;
- invent external IDs, emails, affiliations or reference metadata;
- create citation edges directly.

AI output must pass deterministic schema/foreign-key validation before database mutation.

## 7. Online boundary

Phase 4 is local-first. Broad Internet enrichment of author biography, portraits, education, social profiles, age/gender or monthly updates is outside this phase.

If explicit external identifiers already exist in trusted local/structured evidence, Phase 4 may store them. A future enrichment phase may use them to enrich profiles.

## 8. Review queues

Phase 4 should expose query/service-level review queues for at least:

```text
AMBIGUOUS_AUTHOR_IDENTITY
IDENTITY_CONFLICT
UNRESOLVED_CORRESPONDING_AUTHOR
AMBIGUOUS_REFERENCE_MATCH
REFERENCE_CONTRADICTION
UNRESOLVED_REFERENCE
```

A UI is not required in Phase 4; a deterministic report/query interface is sufficient.

## 9. Invariants

The following are non-negotiable:

1. no source creator row is destroyed by identity resolution;
2. normalized name alone never auto-merges authors;
3. one mention has at most one active accepted author membership;
4. identity merge/split history is reversible/auditable;
5. corresponding author is author-paper scoped;
6. only accepted PDF/reference evidence participates as authoritative semantic evidence;
7. only accepted `paper_reference_match` may later produce `CITES`;
8. no citation self-match is accepted merely because titles/identifiers are malformed;
9. deterministic and AI/manual decisions retain actor/version/evidence provenance;
10. ambiguity is a valid result.

## 10. Phase boundary

Phase 4 ends with resolved author identities, authorship roles, local reference-match decisions and review queues.

It does not end with a web UI, graph visualization or fully enriched author profile. Those consume Phase 4 outputs later.
